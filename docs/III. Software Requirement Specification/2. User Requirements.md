# 2\. User Requirements

### 2.1 System Actors

| **#** | **Actor** | **Description** |
| --- | --- | --- |
| 1 | Developer | Primary user responsible for source code creation and initial documentation. Connects GitHub repositories via OAuth, triggers AST-based AI documentation generation, reviews AI auto-updated drafts after code changes, inspects grounding evidence (code diffs, commits), resolves documentation drift alerts, and submits document drafts into the review workflow. |
| 2 | Staff | First-level technical reviewer responsible for verifying AI-generated and auto-updated documentation before manager approval. Reviews submitted drafts in the queue against source code diffs and dynamic templates, adds section comments or inline feedback, corrects minor errors, and approves to forward to the Manager or rejects back to the Developer. |
| 3 | Manager | Final approval authority controlling whether documentation is published or committed back to the repository. Inspects staff review comments and full audit trails, grants final approval to auto-commit `.md` files to GitHub, configures Pull Request merge policies (warn/block), manages approval delegation, and performs document rollbacks. |
| 4 | Technical Lead | Documentation owner responsible for governance, quality, and standards across repositories. Creates, edits, and maintains dynamic documentation templates, configures drift detection policies and severity thresholds, monitors the documentation health dashboard (freshness, coverage, drift status), and inspects code-to-doc dependency graphs |
| 5 | Administrator | System administrator responsible for system-wide configuration, user management, and security. Sets up Role-Based Access Control (RBAC) permissions, configures GitHub App/OAuth connections and third-party integrations (Jira, Slack), tunes AI engine settings (LLM model selection, embedding models, confidence thresholds, token budgets), and inspects system audit logs. |
