# 6\. Configuration Management

### 6.1 Document Management

- **Main project & engineering documents** (Project Charter, SRS, Architecture & Database Design, Test Plans, Deployment Guides, Meeting Minutes) are maintained centrally on an **Atlassian Confluence workspace** as the single source of truth.
- **Project progress, task execution, and bug tracking** are managed on **Jira** (linked directly to corresponding Confluence documentation pages), while **source code, API specs (OpenAPI), and Docker infrastructure configurations** are stored on **GitHub**.
- Versioning is tracked automatically via **Confluence Page History** and **Jira Release Tags**, using the naming convention: `[LivingDocs] DocumentName_v1.0`, `[LivingDocs] DocumentName_v1.1` for revisions.
- Major updates are logged in the **Record of Changes** page on Confluence and cross-referenced with corresponding **Jira Epics / Releases** and **GitHub Pull Requests**.
- Access rights:
    - **Editors**: Team members (Leader/FE Lead, Backend/DB Lead, AI Specialist, Core/AST Specialist, DevOps/QA Lead).
    - **Viewers**: Stakeholders (advisors, supervisors).
- Weekly backup of all Confluence space pages and Jira project exports (PDF/HTML archives) to a secondary storage (GitHub Repository`/docs` folder) to ensure redundancy.

### 6.2 Source Code Management

- The source code is hosted on **GitHub** using a standard **branching strategy**:
    - `main`: production-ready code.
    - `develop`: ongoing development.
    - `feature/*`: individual feature branches (e.g., `feature/FE04-ast-drift-engine`, `feature/FE01-github-oauth`).
    - `hotfix/*`: urgent fixes to production.
- **Pull Requests (PRs)** must be reviewed by at least 1 peer developer and 1 QA lead before merging.
- **Commit message convention**: `[FE<ID>] Short description` or `[Fix] Short description` (e.g., `[FE04] Implement Tree-sitter AST parser`, `[Fix] Resolve GitHub webhook payload error`).
- **Continuous Integration (CI)** pipeline runs automated **lint checks, unit tests, and build tests** on each PR.
- **Continuous Deployment (CD)** pipeline auto-deploys to **Docker Staging environment** after successful merge to `develop`, and to **production environment** after approval of `main`.
- **Issue tracking** and **task management** are linked through **Jira** and **GitHub Issues**.
